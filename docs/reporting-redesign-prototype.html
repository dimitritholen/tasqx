    RESEARCH SUMMARY — two strands, and where they conflict. TIME-TRACKING CONVENTION (Toggl, Harvest, Clockify, Jira, Linear): - Three-view split is near-universal: Summary (aggregate + chart), Detailed (raw entry list), Weekly (grid). Toggl and Clockify both ship exactly these three. - Recurring charts: stacked bar over a time axis (Toggl bar chart, stackable by project/client/tag), proportional breakdown (Toggl pie), burndown + cumulative flow + velocity + throughput (Jira Scrum reports). - Universal control: a date-range selector with presets, top-left. Grouping selector next to the chart. - Evidence on what is actually used: Atlassian and practitioner guidance both say start with cycle time and burndown; CFD and velocity are for mature teams. Dashboard research (Bach et al., "Dashboard Design Patterns", IEEE VIS 2022 / TVCG 2023, n=144 dashboards) catalogues eight pattern groups; the practitioner literature converges on 5-7 primary KPIs per view and warns that vanity metrics (impressive totals nobody acts on) crowd out actionable ones. AI TOKEN CONVENTION (Anthropic Console/Usage API, Langfuse, LangSmith, Helicone): - Four buckets, always separate: uncached input, cached input, cache creation, output. Anthropic Usage API groups by model/workspace/service_tier over 1m/1h/1d time buckets. - Anthropic keeps USAGE and COST as two different endpoints. Cost is derived, not the same question. - Langfuse: buckets are mutually exclusive by contract; cost attributed per observation, rolled up per trace. - Cache economics: cache read = 0.1x input price, cache write = 1.25x input price. WHERE THEY CONFLICT: 1. Blending. Time reporting blends freely — hours are hours, so "12h this week" is a true headline. Token reporting must not blend: four buckets at 0.1x-1.25x relative price make one total meaningless. TOKEN CONVENTION WINS. tasqx already agrees in core (reports.rs:73) but violates it in the presentation layer (html.rs:273 renders one blended stat("AI tokens")). 2. Time axis. Token dashboards are time-series first (bucket_width is a required-feeling param). Time-tracking reports are entity-first (per project/client/task) with time as a secondary axis. For tasqx the unit of work is the TASK, so ENTITY-FIRST WINS — tokens per task/project, with time as the secondary axis. This is also what the API supports: report.summary group_by is project|status|priority with no time axis at all. 3. Cost. Every AI tool shows currency. tasqx must NOT: it has no pricing table, no model-price feed, and prices change. Show tokens and time as the two costs; leave money out. TIME-TRACKING CONVENTION WINS (Harvest shows revenue only because the user entered rates). DECISION TAKEN (user, this session): adopt the docs.rs self-containment guard shape for html.rs — in-page #anchors and one inline <script> become legal; per-href assertion plus url(/<link>/@import bans are added. Self-containment is preserved, and net tightened.

    FRAMEWORK DECISION: hand-rolled vanilla JS. ~2.5 KB of inline script, no vendored library. MEASURED SIZES (curl + wc -c, 2026-07-25, not quoted from bundlephobia): uplot@1.6.32 uPlot.iife.min.js 51081 B raw 21991 B gzip uplot@1.6.32 uPlot.min.css 1857 B raw 758 B gzip preact@10.26.9 preact.min.js 11195 B raw 4762 B gzip htm@3.1.1 htm.js 1265 B raw 678 B gzip alpinejs@3.14.9 cdn.min.js 44758 B raw 16171 B gzip CORRECTION TO THE BRIEF: gzipped size is the wrong metric here. The page is opened over file:// with no HTTP transport, so nothing decompresses it — the browser parses the raw bytes. And include_str! embeds raw bytes into the binary. Gzip only matters if someone mails the .html and the mail client compresses it. Judge on RAW. WHY NOT uPlot (the strongest candidate): it would be a SECOND chart implementation. chart.rs already computes the geometry in Rust and html.rs already emits inline SVG from it (svg_throughput, svg_burndown, ramp_stops as a linearGradient). uPlot draws to <canvas> at runtime, which means (a) 53 KB raw on every page and in the binary, (b) the charts no longer exist in the document — `report --html | head`, a mail preview, a text extraction or a print stylesheet all get an empty box where a chart was, and DESIGN 8 sells this file as mailable/committable/air-gapped, i.e. as a DOCUMENT, (c) canvas output is not selectable, not searchable and not themeable by the CSS custom properties the rest of the page uses. WHY NOT Preact+htm (12.5 KB raw): it buys a component model for a page that is generated once, server-side, and never re-renders from changing state. There is no state to diff. Rust already owns templating and already owns the one escaper (html::esc, D19) — moving rendering into JS templates would create a SECOND escaping path, which is precisely the drift D19 exists to prevent. WHY NOT Alpine (44.8 KB raw): 18x the vanilla budget to express show/hide. x-cloak/FOUC handling needs the runtime parsed before first paint, and its directives live in HTML attributes, i.e. in the same strings that carry untrusted task text — an attribute-directive framework and an untrusted-text surface is a combination worth avoiding on principle. LICENSES: uPlot MIT, Preact MIT, htm Apache-2.0, Alpine MIT — all on deny.toml allow[]. But that is a MANUAL claim, not a guarded one: deny.toml is cargo-deny config and only sees the Rust crate graph. A vendored .js blob under include_str! is invisible to `cargo deny check licenses` forever. Vendoring any of these means adding a license obligation that no CI gate can see, plus a manual upgrade path with no `cargo update` and no advisory feed. That asymmetry is on its own close to decisive. WHAT VANILLA HAS TO DO (the whole interaction budget): 1. toggle a token bucket on/off in the legend -> one classList flip on a container, CSS does the rest 2. click a project row -> filter the timeline -> set a data-filter attribute on <main>, CSS attribute selectors hide non-matching rows 3. open a task -> :target CSS, zero JS 4. deep link + back button -> location.hash + hashchange (pushState throws SecurityError on file://, DESIGN 8a) Estimated ~2.5 KB raw, no build step, no minifier in the build, readable in the generated file. BINARY COST: vanilla ~2.5 KB; uPlot would be ~53 KB; Alpine ~45 KB. Against a release binary in the megabytes these are small in isolation — the argument against them is not size, it is the second implementation, the second escaper, the invisible license and the chart that stops existing when JS does not run.
